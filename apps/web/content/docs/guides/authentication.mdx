title: Authentication
description: Drive the agent-agnostic auth step-flow — list methods, begin, step, and check status.
---

Each agent authenticates once with its own credentials, but MindWire normalizes the flow to four
calls: **list methods → begin → step → status**. A method is either non-interactive (collect fields
like an API key, then `step`) or interactive (open a `url`, then `step` polls to completion).

## The state machine

`begin` and `step` both return an `AuthState` whose `status` drives what you do next:

| `status` | What it means | Next |
| --- | --- | --- |
| `needs_input` | The method wants fields (see `fields`). | `step` with the values. |
| `pending` | Interactive login in progress (`url`/`code` set). | `step` again to poll. |
| `complete` | Authenticated. | Done. |
| `error` | Failed (`message` explains). | Restart with `begin`. |

## List the methods

Present the options the agent offers.

<ApiTabs>

<Tab value="TypeScript">

```ts
const methods = await mw.auth.methods();
for (const m of methods) console.log(m.id, m.label, m.interactive ? "(interactive)" : "");
```

</Tab>

methods, err := client.Auth.Methods()

## Non-interactive: API key

Begin the method, then submit the fields it asked for.

<ApiTabs>

<Tab value="TypeScript">

```ts
await mw.auth.begin("apiKey");                    // → { status: "needs_input", fields: [...] }
const state = await mw.auth.step({ apiKey: "sk-ant-..." });
console.log(state.status);                        // "complete"
```

</Tab>

<Tab value="Go">

```go
client.Auth.Begin(ctx, "apiKey")                  // → status "needs_input"
state, err := client.Auth.Step(ctx, map[string]string{"apiKey": "sk-ant-..."})
if err != nil {
	log.Fatal(err)
}
fmt.Println(state.Status)                          // "complete"
```

</Tab>

<Tab value="REST">

```bash
curl -XPOST 'http://127.0.0.1:8790/auth/begin?agent=claude-code' -d '{"method":"apiKey"}'
curl -XPOST 'http://127.0.0.1:8790/auth/step?agent=claude-code'  -d '{"apiKey":"sk-ant-..."}'
```

</Tab>

</ApiTabs>

## Microsoft Foundry

For a normal API-key connection, enter **endpoint URL, API key, and deployment name**.
Copy the URL and key from your Azure resource's **Endpoints and keys** page, and use the
exact name from its model deployments. A deployment name may differ from the public model name.

| Agent | Method | Endpoint | Input keys |
| --- | --- | --- | --- |
| Codex | `azureFoundry` | `https://RESOURCE.services.ai.azure.com/openai/v1` | `azureBaseUrl`, `azureApiKey`, `azureModel` |
| Claude Code | `foundry` | `https://RESOURCE.services.ai.azure.com/anthropic` | `foundryBaseUrl`, `foundryApiKey`, `foundryModel` |

A bare HTTPS resource URL is accepted; Mindwire adds the matching API path. Codex also supports
`openai.azure.com` resources. Its OpenAI v1 endpoint needs no `api-version` query parameter.
The OpenAI and Anthropic API paths are different and cannot be swapped between agents.

The form has three sections: **Connection details**, **Authentication**, and **Deployment name**.
Connection details has a **URL / Resource name** switch. Authentication has an **API key / Entra ID**
switch; Claude also offers **Azure sign-in** for credentials already available in the workspace.
Only the inputs for the selected options are shown and required.

| Choice | Codex selector | Claude selector | Values |
| --- | --- | --- | --- |
| Endpoint | `azureEndpointType` | `foundryEndpointType` | `url` (default), `resource` |
| Authentication | `azureAuthType` | `foundryAuthType` | `apiKey` (default), `entraToken`; Claude also accepts `azureCredentials` |

With `resource`, send `azureResource` / `foundryResource`. With `entraToken`, send
`azureAuthToken` / `foundryAuthToken`. Explicit selections always win: hidden URL or credential
values are discarded before validation and persistence. **Azure sign-in** collects no credential;
Azure sign-in or a managed identity must already be available in the agent's workspace.
An explicit Claude Entra token requires Claude Code 2.1.203 or later.

Older clients can still submit the three input keys in the first table without selectors.
For those requests, a URL takes precedence over a resource name, a token over an API key, and
Claude uses workspace Azure credentials when neither credential is supplied.

Claude uses `foundryModel` for its default model, model aliases, and background tasks, so one deployed
Claude model is sufficient. Codex uses `azureModel` as its `model` value. An explicit turn model can
override either default, and must name a deployment available on the selected Azure resource.

`GET /auth/methods` and `POST /auth/begin` declare the entire form. Clients render `sections` in
order using each section's `title` and `fieldKeys`, with native controls for the field types.
Resolve field `default` values before evaluating `visibleWhen: { key, equals }`; validate and submit
only visible fields. Selects may request `presentation: "segmented"`, and URL inputs declare
`inputMode: "url"`. Show field `help` and the selected option's `help` in section footers.
Keep the Connect action outside the scrolling form, above the keyboard on mobile.
Older daemons without sections can render each field under its own label; `requiredUnless`
continues to support legacy alternative fields.

Provider references: [Microsoft's endpoint guide](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/how-to/switching-endpoints),
[Codex provider configuration](https://developers.openai.com/codex/config-reference/), and
[Claude Code on Foundry](https://code.claude.com/docs/en/microsoft-foundry).

## Interactive: browser sign-in

`begin` returns a `url` (and sometimes a `code`) to show the user; then `step` **polls** until the
login completes.

<ApiTabs>

<Tab value="TypeScript">

```ts
let state = await mw.auth.begin("login");
console.log("Open:", state.url);                  // show the user this URL

while (state.status === "pending") {
  await new Promise((r) => setTimeout(r, 1500));
  state = await mw.auth.step({});                 // poll
}
console.log(state.status);                         // "complete"
```

</Tab>

<Tab value="Go">

```go
state, err := client.Auth.Begin(ctx, "login")
if err != nil {
	log.Fatal(err)
}
fmt.Println("Open:", state.URL)

for state.Status == "pending" {
	time.Sleep(1500 * time.Millisecond)
	if state, err = client.Auth.Step(ctx, map[string]string{}); err != nil {
		log.Fatal(err)
	}
}
fmt.Println(state.Status) // "complete"
```

</Tab>

<Tab value="REST">

```bash
# begin returns {"status":"pending","url":"https://…"}; poll step until "complete".
curl -XPOST 'http://127.0.0.1:8790/auth/begin?agent=claude-code' -d '{"method":"login"}'
curl -XPOST 'http://127.0.0.1:8790/auth/step?agent=claude-code'  -d '{}'
```

</Tab>

</ApiTabs>

## Check status

Whether the agent is authenticated, and via which method.

<ApiTabs>

<Tab value="TypeScript">

```ts
const { configured, method } = await mw.auth.status();
if (!configured) console.log("run the auth flow first");
```

</Tab>

<Tab value="Go">

```go
status, err := client.Auth.Status(ctx)
if err != nil {
	log.Fatal(err)
}
if !status.Configured {
	fmt.Println("run the auth flow first")
}
```

</Tab>

<Tab value="REST">

```bash
curl -s "http://127.0.0.1:8790/auth/status?agent=claude-code" | jq '{configured, method}'
```

</Tab>

</ApiTabs>

> Credentials only ever flow through the auth module and are injected into the agent process at run
> time — they're never returned by the API, never stored in config, and never travel on a turn.

This flow authenticates the **agent**. It's distinct from the transport-level credentials used to reach
a daemon at a non-local [destination](/docs/guides/destinations) — e.g. the Oblien sandbox credentials
(client id/secret) and the short-lived gateway JWT — which the SDK manages for you.
