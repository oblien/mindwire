---
title: Personal computers
description: Pair your phone with a Mac, Windows PC, or Linux computer and use the same Mindwire workspace, agents, files, Git, and terminal.
---

Run Mindwire on your computer and pair it with the mobile app. The computer becomes
a workspace: projects, agents, chats, approvals, files, Git, and terminal tabs use
the existing workspace APIs. An Oblien account is not required.

## Connect a computer

Install Node.js 18 or later, then run:

```sh
npm install -g mindwire
mindwire connect
```

The default **Automatic** option uses a free Cloudflare tunnel and Mindwire’s
encrypted address directory. **No Mindwire or Oblien login is needed.** Pair once
by QR; your computer publishes its changing tunnel address under its stable key,
and your phone uses its saved key to find it again.

You can also choose **Oblien**, **your Cloudflare account**, **ngrok**, **your VPN**,
an **existing tunnel**, or **temporary Cloudflare without address recovery**.
Named tunnels keep the same internet address across computer and tunnel restarts.
Provider login is needed only for the account-based provider you choose.

Mindwire downloads a verified daemon release and starts it in the background.
Cloudflare's helper is downloaded into a private cache when needed; ngrok uses its
official agent SDK. You can connect from another Wi-Fi network or mobile data.

For a first connection, Mindwire asks whether to start automatically after computer
login, then displays a QR code. In the mobile app, open **Add computer** and
scan it, or paste the pairing link. Approve the phone in the computer's terminal;
the device name and key fingerprint appear on both sides. The invitation expires
after five minutes.

Once paired, the app opens the computer's workspace. Create a project or select an
existing folder, add an agent, and use its normal authentication and chat flow.
**Open terminal** starts a native shell on the computer.

Mindwire runs with the permissions of the computer user who started it. The initial
folder defaults to that user's home; `--directory /path/to/projects` changes the
initial folder, not the filesystem permissions or sandbox boundary. Git features
need Git. On Windows, install Git for Windows for its Bash support as well. Harness
availability still depends on the harness's operating-system requirements.

You can close the pairing terminal after approval. With automatic startup enabled,
Mindwire runs after you sign in to the computer. It retries
dropped tunnels and recovers the background controller without restarting a healthy
daemon. The computer must remain awake and online.

Choose a persistent connection with `mindwire connection`, or enable encrypted
address recovery as described below. A temporary quick tunnel can get a new address
after a restart. Without address recovery, if all saved addresses change while
the phone is away, run `mindwire connect pair` and scan once to refresh the address.
This keeps the same computer identity, workspace and projects.

### Return to a saved connection

Run `mindwire connect` again. With a persistent address or an acknowledged address
recovery key, and a saved approval, it
starts the background connection without another QR. “Ready for your saved phone”
means the address is available; “Connected” is shown only after a phone authenticates.
Open the mobile app to reconnect with its saved key.

```sh
mindwire connect          # Set up a first connection or resume an existing one
mindwire reconnect        # Retry the saved connection
mindwire connect pair     # Show a QR to pair or repair a phone
mindwire connection       # Change provider without restarting the daemon
```

Open **Computers & Servers → your computer → Reconnect** in the app. Use **Repair**
to scan a fresh code, or scan through **Add computer**. These reuse the same workspace. A saved phone proves
it still owns its approved key; a new key needs your approval on the computer.
The terminal confirms success after the phone saves its connection.

If you removed the connection or reinstalled the app, the computer may still list
the old approval. When approving the new key, choose **replace** for the listed
old approvals or **add** for a different phone. Two phones can share the name
“iPhone,” so Mindwire never replaces keys just because their names match.

Older address-only reconnect codes require the phone's saved key. If it is missing,
update Mindwire on the computer and run `mindwire connect pair` for a fresh connection code.

### Automatic startup

```sh
mindwire startup status
mindwire startup enable
mindwire startup repair
mindwire startup disable
```

Mindwire uses launchd on macOS, a systemd user service on Linux, and Task Scheduler
on Windows. No administrator service or password is required. If native startup
is unavailable, the CLI says so and the current connection still works. Use
`mindwire start` to start it manually. The first-time startup choice is remembered;
`mindwire connect --no-startup` skips setup and an explicitly disabled preference stays disabled.
Scripts can use `--startup` to opt in; noninteractive runs do not enable startup by default.

`mindwire stop` keeps the service stopped, including after login, until you run
`mindwire start` or `mindwire connect`. Disabling automatic startup leaves an
already-running workspace alone.

### Manage this computer

Run `mindwire` without arguments to open the interactive menu. It shows the actual
service version, connected phones, automatic recovery and startup health. Use the
arrow keys to reconnect, repair a phone, change providers, manage startup, update
the service, inspect details or stop Mindwire. **Exit** closes only the menu.

```sh
mindwire status            # Compact status, even when the service is stopped
mindwire inspect           # Addresses, identity, pending updates and diagnostics
mindwire --version         # Installed CLI version
mindwire update            # Update the background service; preserve active work
mindwire update --force    # Restart now, closing active sessions and terminals
```

After the next start or reconnect, an updated CLI schedules its matching managed service release.
An automatic update waits for active work to finish; an explicit **Restart now**
or `--force` can proceed immediately. Concurrent requests join the current update.
If an older update is already pending, it completes first.

Legacy quick Cloudflare connections automatically enroll in address recovery
unless it was explicitly disabled. Enrollment retries after an outage, including
after a restart. A saved phone must connect once to learn its recovery key; until
then, status says **Finish setup on your phone**. If all old addresses are already
gone, use **Repair** once. Named tunnels, VPNs and explicit temporary connections
keep their chosen setup.

## Choose a connection

SSH supplies authentication and encryption on every route. Choose the network
route according to how the phone can reach the computer:

| Route | Needs a relay? | Suitable for |
| --- | --- | --- |
| Oblien, named Cloudflare, or reserved ngrok domain | Yes | Persistent internet access without inbound port forwarding |
| Cloudflare + Mindwire address directory | Cloudflare carries traffic | Finding a changed address with the phone's existing pairing key |
| Temporary Cloudflare | Yes | Trying the app without an account; a restart may need an address refresh |
| Existing VPN, including Tailscale | Depends on the VPN's connectivity | Regular use across networks with a stable address |
| Custom WebSocket tunnel | Your provider | An existing tunnel or self-hosted relay |
| Reachable public address | No | A host with an existing secure network setup |
| Same reachable Wi-Fi/LAN | No | Optional local use with no external service |

Two devices behind unrelated NATs need a reachable address, VPN, or relay. The QR
code establishes trust; it does not create a network path by itself. This protocol
does not depend on Apple Continuity or on both devices using the same operating
system.

The default direct listener is TCP port **8791**. Mindwire leaves the computer's
system SSH configuration unchanged. Allow that port on the intended network if
the computer's firewall blocks it.

### Direct SSH or an existing VPN

Mindwire can also advertise the computer's available LAN/VPN addresses alongside
its internet route. To use direct SSH alone, explicitly disable the relay:

```sh
mindwire connect --relay none --host laptop.local
mindwire connect --relay none --host laptop.your-tailnet.ts.net
```

For Tailscale, connect the phone and computer to the same tailnet first. Mindwire
then uses its own paired SSH identity over the VPN. It does not configure the VPN
or require Tailscale SSH.

### Oblien

```sh
mindwire connection oblien
```

Sign in through the browser. Mindwire creates a named tunnel for this computer and
keeps its tunnel ID and `*.preview.oblien.com` address. It never selects another
computer's tunnel just because it uses the same port. No cloud workspace is required.
Your plan's tunnel and bandwidth allowances apply.

The official Oblien SDK carries traffic to the local SSH WebSocket bridge.
Mindwire renews the broker token in advance and uses the new token on reconnect,
without replacing a healthy connection just to rotate credentials. The browser
session is stored privately on the computer and renewed while it is valid. If the
computer stays offline beyond the login's expiry or the login is revoked, run
`mindwire connection oblien` to sign in again. A persistent address does not bypass
account revocation or expiry.
Signing in again at the same address keeps the phone's saved pairing and does not
require another QR.

### Encrypted address recovery

Address recovery uses the existing Mindwire Console backend without a website
account. If the updated backend is unavailable, setup reports the problem and
preserves an existing connection.

```sh
mindwire connection automatic  # Free Cloudflare carrier + Mindwire address discovery
mindwire discovery enable      # Add discovery to your current provider
mindwire discovery status
mindwire discovery disable
```

The computer proves its saved SSH key to register and publish encrypted address
updates. Your phone learns the directory URL and its decryption key through the
paired SSH connection. No browser login, matching account or account token is
needed on either device.

You can use your [self-hosted Mindwire Console](https://github.com/oblien/mindwire/tree/main/apps/console)
as the directory. It uses the same server and persistent database; its normal
website login remains separate. Set its stable HTTPS URL on the computer:

```sh
mindwire discovery enable --directory-url https://console.example.com/api/computer-directory/v1
```

The CLI also accepts `MINDWIRE_DIRECTORY_URL`. It uses the explicit flag first,
then the environment variable, then a saved URL, then Mindwire’s hosted default.
Your phone learns the chosen URL automatically; it has no hardcoded directory.

A saved directory stays selected across upgrades. Disable and withdraw the old
directory before changing URLs, then reconnect each phone once to save the new
discovery key. A computer’s stable key and directory URL let the phone discover
a new Cloudflare address without repeating QR pairing.

The directory stores signed, encrypted address records. Files, chats, terminals
and desktop traffic continue through the selected SSH carrier. Publication happens
when addresses or approvals change, with a renewal every 12 hours. The phone tries
cached routes immediately and looks up a replacement when connection is slow or
fails. A directory outage does not prevent a working cached route from connecting.

After enabling on an already paired computer, open each phone once while its
current address still works. That saves the discovery key without changing its
workspace or phone identity. If the old address was already lost before this
upgrade, scan one new pairing code. Keep the computer awake, online and running
Mindwire; discovery does not wake sleeping hardware or replace an unavailable
tunnel provider.

### Cloudflare

```sh
mindwire connection cloudflare
```

Enter a hostname in your Cloudflare zone and complete Cloudflare's browser login.
Mindwire creates a named tunnel, assigns its DNS hostname, and writes a local
configuration forwarding only the SSH WebSocket bridge. It does not overwrite an
existing DNS record that belongs to another service. Your domain and tunnel remain
in your own Cloudflare account.

A quick tunnel is also available and works across networks without a Cloudflare
account. Mindwire reuses `cloudflared` if installed or downloads a pinned, verified
copy for its own use:

```sh
mindwire connect --relay cloudflare
```

Quick tunnel hostnames change when the tunnel restarts. **Automatic** handles
these changes through the directory. Another option is a named tunnel with a
stable public hostname. Configure that hostname to forward to
`http://127.0.0.1:8792`, save its tunnel token in a private file, and run:

```sh
mindwire connect --relay cloudflare \
  --relay-url wss://computer.example.com/ssh \
  --cloudflare-token-file /path/to/private/tunnel-token
```

Mindwire passes the token to `cloudflared` through its environment and does not
include it in the QR code. Browser sign-in challenges in front of the tunnel are
not supported by this native connection; Mindwire's SSH keys authenticate devices.

### ngrok

Use your account's reserved domain, including a dev domain where your plan supports it:

```sh
mindwire connection ngrok
```

Mindwire opens the ngrok dashboard. Copy an authtoken into the hidden terminal
prompt and enter your domain. The official ngrok agent manages its heartbeat and
reconnect using that same domain. Each computer needs its own address. The token
stays on the computer and is never included in pairing codes.

An already installed and configured ngrok CLI also remains supported:

```sh
mindwire connect --relay ngrok --relay-url wss://your-host.ngrok.app/ssh
```

### Existing or custom tunnels

Any tunnel that supports binary WebSocket connections can carry this protocol.
Forward its public `/ssh` route to `http://127.0.0.1:8792/ssh`, then advertise it:

```sh
mindwire connect --relay custom --relay-url wss://computer.example.com/ssh
```

The custom adapter advertises an already-running tunnel; the provider owns that
tunnel's lifecycle. Use it for a self-hosted relay or another provider.

With a relay, SSH bytes travel inside WSS. The phone still pins the computer's SSH
key, so TLS termination at the provider does not expose workspace content. The
daemon's authenticated HTTP API remains on loopback and is reached through SSH
forwarding. Do not point a tunnel directly at that HTTP API.

Direct and relay routes can coexist. The app selects an authenticated route before
sending workspace requests and learns current addresses from the verified computer.
Use `mindwire connection` to change providers. The controller keeps the old service
running while it starts and verifies the replacement route. Failed setup leaves the
previous configuration in place. A successful provider change shows a QR to save
the new address once; subsequent reconnects use it automatically. The computer
identity, projects and running daemon are retained. Changing listening ports or the
initial service directory still requires stopping when idle.

Refreshing credentials for the same reserved Oblien/ngrok endpoint briefly
reconnects the tunnel. A failed refresh restores the prior provider settings;
terminals and agents keep running. `mindwire status` reports the provider and the
result of a connection change. Provider login and certificate failures are shown
directly instead of waiting for a generic connection timeout.

## Terminals and reconnecting

The daemon owns terminal sessions. Leaving the terminal view or losing the phone's
connection detaches the client; it does not kill the shell. Returning restores the
same terminal, recent output, and live input. Closing a terminal tab explicitly
terminates that shell.

Output replay is bounded to 2 MiB per terminal. If a client falls behind that
window, it receives the current terminal screen and resumes from there. Input
uses sequential receipts so retrying a lost acknowledgment does not type a command
twice. macOS/Linux use a PTY; Windows uses ConPTY.

iOS detects Wi-Fi/mobile-data changes, waits while offline, and retries saved
computers while active with a delay capped at one minute. Backgrounding pauses this
work; foregrounding retries immediately. Successful checks stay cached between
screens. Chat, files and terminal clients share the same authenticated SSH endpoint;
closing one view does not close another view's connection. A rejected phone key or
changed host identity stops automatic retries and requires explicit repair.
Tunnels retry independently, including while a service update waits for idle work.

On current daemons, Send uses a durable request ID. If its acknowledgement is lost,
retrying returns the original run instead of submitting the message again. API/SDK
clients can provide `requestId` to `turn`/`resolve` when `/healthz` advertises
`turnRequestVersion: 1`; keep the same ID and payload when retrying.

Terminals survive client disconnects, not a computer reboot or daemon restart.
The controller waits for running shells and other work before updating.

## Devices and updates

```sh
mindwire status
mindwire devices
mindwire revoke DEVICE_ID
mindwire stop
```

Each paired phone has its own key. Revocation closes that phone's active
connections, pending pairing sessions and private forwards, and rejects reconnects.
It does not undo commands already executed. Pairing keys and daemon credentials stay
in that phone's Keychain and do not migrate onto another phone through a backup;
cached workspace metadata contains only credential references.
Computer state is stored under `~/.mindwire/computer` by default.

To update the CLI and service:

```sh
npm install -g mindwire@latest
mindwire update
```

The controller downloads and verifies the release, waits for agent runs, workspace
operations, pairing, and terminals to finish, then obtains the daemon's update
lease. Concurrent requests share the update. If the replacement fails its health
or version check, the controller restores the previous binary.

`mindwire stop` refuses to interrupt active work. `mindwire stop --force` explicitly
ends it. `--state-dir PATH` selects a separate private service state directory.

## Protocol and scope

The daemon advertises `computerConnectionVersion`, `workspaceExecutionVersion`,
and `terminalProtocolVersion` in `/healthz`. Personal connections add pairing and
transport; agent streaming, questions, approvals, projects, Git, and authentication
continue through the standard daemon protocol.

The SDK exposes native workspace execution through `client.execution` and computer
management through `client.computer`. See the generated REST and SDK reference for
file, resource, command, terminal, pairing, and update contracts.

With `pairingVersion: 3` from `/computer`, the phone signs every `POST /pair`,
including approval polling and retries. `GET /pair/{id}` returns status without
credentials. Existing clients that sign their requests keep working; unsigned
pairing clients must update. Pairing sessions close when their invitation expires.

The mobile implementation is currently iOS. The wire protocol can support other
clients, but this feature does not add an Android app. Personal desktop capture and
off-device push delivery are separate capabilities from workspace and terminal
access.
