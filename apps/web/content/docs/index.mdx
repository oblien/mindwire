Mindwire is an open-source SDK and runtime for adding agent capabilities to your product.
Start tasks, stream progress, handle supported approvals, and continue conversations through
TypeScript, Go, or REST and SSE. Your application supplies its interface, authorization,
and the context and tools its users need.

**Codex, Claude Code, Grok Build, and OpenCode are supported today.** Their available tools and
permissions determine which files, scripts, browsers, or applications a task can use. Check
capabilities when designing an integration.

The [Mindwire app](/app) is a first-party application built on the same runtime, with General and
Developer modes. It is optional for SDK integrations. See [Download](/download) for Mac and iOS
availability. [Mindwire Cloud](/cloud) offers optional monthly computers; Console manages those
computers and accounts. You can also run the SDK and runtime on infrastructure you manage.

The runtime, SDKs, and web console are open source under Apache-2.0. The Apple client is
source-available under a separate license that allows inspection and private personal builds;
redistribution and publishing derivative apps require written permission. See the repository’s
[component licenses](https://github.com/oblien/mindwire/blob/main/LICENSING.md).

## For developers

The Go runtime owns agent processes and exposes a common protocol for turns, streaming,
authentication, sessions, and workspace tools. Build with the TypeScript SDK, native Go SDK,
or REST and SSE. Run locally, remotely, over SSH, in Docker, or in an Oblien workspace.

Each harness keeps its native execution and session semantics. Check its advertised capabilities
instead of assuming every engine implements every tool or session operation.

## Install

<ApiTabs>

<Tab value="TypeScript">

```bash
npm i mindwire
```

The SDK ships the daemon with the package and **runs it for you locally** — nothing to deploy.

</Tab>

<Tab value="Go">

```bash
go get github.com/oblien/mindwire/packages/daemon
```

The Go SDK (`.../packages/daemon/sdk`, package `mindwire`) is the daemon's own engine, **in-process** — no
HTTP hop, no subprocess.

</Tab>

<Tab value="REST">

```bash
go -C packages/daemon run ./cmd/daemon
```

Run the daemon standalone for a plain **HTTP + SSE** API — any language, no SDK.

</Tab>

</ApiTabs>

## The pieces

| Component | What it is |
| --- | --- |
| `mindwire` (TS) | The TypeScript SDK — auto-runs the bundled daemon locally. |
| `.../packages/daemon/sdk` (Go) | The native in-process Go SDK — the daemon's core as a library. |
| daemon | The Go core (`mindwired`) that owns the agent processes; runs embedded, or standalone over HTTP + SSE for remote/self-host. |
| adapters | One drop-in folder per agent. `claude-code`, `codex`, `grok`, and `opencode` today; `copilot` next. |

## Why it exists

Every coding agent ships its own CLI, flags, and auth. Model APIs converged on one standard and are stateless; agent harnesses did **not**, and they're stateful and side-effecting. MindWire is built around exactly those hard parts:

- **Durable sessions.** A turn keeps running if the client disconnects; reattach to its live stream.
- **A unified event stream.** `text`, `thinking`, `tool_use`, `tool_result`, `result` — every agent, one shape.
- **A capabilities matrix.** Each adapter declares supported features so your application can handle differences explicitly.
